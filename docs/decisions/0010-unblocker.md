# 0010 Unblocker

Status: accepted (issue #106; design 0002 unblocker role, built on design 0004 untrusted-text boundary).

When an agent parks an item with `needs-human`, the unblocker looks at the block before Daniel does. `.github/workflows/unblocker.yml` starts on the `needs-human` label event. `tools/unblock.py gate` lets it continue only for an open item that still has the label, set by the author app, the approver app or Daniel, with no `unblock:1` yet; `risk:security` PRs and design PRs always stay with Daniel. `fetch` writes the item text as masked, capped files. A sonnet step with no app token and no Bash (`.agents/roles/unblocker.md`) reads them as data and writes one `verdict.json`; `tools/unblock.py validate` and `apply` do everything else. Class 1 (wrong assumption) posts a correction, removes `needs-human`, adds `unblock:1` and restarts the task once; a second block on the same item goes to Daniel. Class 2 (agent infrastructure bug) opens one `prio:1` issue and keeps the label. Class 3 (owner decision) keeps the label and ends with a German note to Daniel as the last comment. The unblocker grants no permission and edits no file. `UNBLOCKER=off` disables the job, and the orchestrator skips items the unblocker owns.
